# Build journal - M2B controlled real public-data pilot

**Date:** 2026-10-04

**Problem:** M2A provided safe local public-company Evidence ingestion, but a real-data pilot needed to prove the existing deterministic Signal -> State -> Decision -> Policy -> Action reasoning path and preserve source provenance without implying validated ICP, external work, or commercial outcomes.

**Evidence / context:** The accepted M2B design and user amendments constrain the market to B2B sales enablement software vendors, 18 selection-blind base accounts plus two disclosed trace-coverage accounts, an explicitly frozen semantic timestamp, one profile fact and the existing new-revenue-leader fact, one pilot Signal, a narrow public Fit criterion, manual source verification, and local-only exposure. The three G2 category pages visibly featured a 23-domain seller frame; the full category reported 194 products, but the frame was not a representative sample. Official company pages support 20 bounded profile observations, with three retained as INCONCLUSIVE. Official dated company news supports one fresh base event and one stale coverage event.

**Hypothesis:** The existing M1 reasoning and governance semantics can produce a truthful, inspectable technical trace from verified public company-level Evidence with no outreach or CRM effect. Fit MATCH would support only the narrow official offering criterion.

**Decision:** ADR-016 freezes manifest v2 at `2026-10-05T00:00:00Z`, preserves v1 as a superseded audit artifact, separates base and coverage summaries, keeps the fresh coverage slot unmet (`PILOT_COVERAGE_NOT_MET`), adds only `account_profile.offers_sales_enablement_software`, and versions a 14-day profile-observation Fit rule in State engine 1.1.0. The M1 Signal, Decision, Policy, and Action evaluators are unchanged. Manual acceptance gates explicit downstream stages. The local pilot API is production-disabled.

**Implementation:** A separate real-data workspace and StrategyVersion 0.1.0 carry one bounded market-listing FACT and five explicit GTM HYPOTHESES. Twenty selected companies, 20 profile rows, and two dated leader rows are recorded in bounded public artifacts with manual verification metadata. Two M2A batches accepted all 22 rows with no unresolved, rejected, duplicate, or conflict result. Local validation binds each CSV company name, cohort, official URL, source observation time, event date, assertion, and paraphrase to the manual verification ledger; tampered dates fail before import. Explicit local commands perform setup, validation, import, row inspection, acceptance, Signals, Signal inspection, State with Signal-recompute identity assertion, State inspection, Decisions, Policies, Actions, and trace/fingerprint export. A recruiter-readable local `/pilot` view labels real evidence, frozen time, cohort separation, limitations, and the full trace. No database migration or provider integration was needed.

**Validation:** The first accepted run materialized 20 Signals, 20 immutable State snapshots, 20 Decisions, 20 Policies, and one REQUEST_RESEARCH Action proposal. BASE_SAMPLE: Signal DETECTED 1 / INCONCLUSIVE 17; Fit MATCH 15 / INCONCLUSIVE 3; Decision ENGAGE 1 / ABSTAIN 17; Policy REQUIRE_REVIEW 1 / BLOCK 17. TRACE_COVERAGE: Signal STALE 1 / INCONCLUSIVE 1; Fit MATCH 2; Decision HOLD 1 / ABSTAIN 1; Policy BLOCK 2. All 20 Relationships were UNKNOWN. No ABSENT, NO_MATCH, NO_ACTION, ALLOW, external attempts, or commercial outcomes were created. A second full stage replay reported zero new identities, reused 20/20/20/20/1, and reproduced semantic SHA-256 `0f4a444ce682e39178bfe9816f5a934634b108c4e1e971de18fddb9cd8c531aa`. Signal recomputation matched exact IDs, hashes, results, and State links. The Action-to-source-observation chain is asserted in an integration test. Northstar seed code and synthetic fixtures were not changed; Northstar account count remained three through the pilot integration replay; 14 core Northstar semantic tables in the populated pilot database and clean regression database produced the same SHA-256 `1c44dddc3c5b299175ab0fc9c2feb94cea52751b90faa6d7aa1361587b2c619a`; public reads stay pinned to its workspace. The actual local API returned the accepted 18/2 trace and expected fingerprint; production mode returned 404 for the pilot API and only the three Northstar accounts on the public account route; the production web pilot page returns not-found before fetch.

Full checks passed: 86 API unit tests, 64 PostgreSQL integration tests in a freshly migrated isolated database (including 63 M0-M2A and one M2B), 17 frontend tests, Python/TypeScript type checks, Ruff/ESLint lint, Ruff/Prettier format, generated-contract drift, and production Next.js build. The CI-pinned gitleaks v8.30.1 working-tree scan covered about 4.95 MB and found no leaks. A separate 30-file changed-content check found no private-key, credential-assignment, cloud-token, email, phone-like excerpt, or overlong CSV excerpt pattern. `git diff --check` passed. No M2B migration was introduced.

**Result:** The pilot demonstrates system reasoning, fixed-snapshot timing, source provenance, and review governance over selected real public company-level evidence. It does not demonstrate commercial fit, buying intent, market prevalence, outreach, seller execution, response, meeting, opportunity, conversion, or revenue.

**Failure / learning:** The five-domain coverage queue did not yield a verified fresh event; the unmet slot is preserved in the ledger and UI. One fresh event occurred naturally in the base sample. The manually transcribed featured-page frame is convenience constrained, and its distributions cannot be generalized to the market. Dynamic source pages and non-republication of raw directory content mean the frozen frame is hash-reproducible but the historic page display may not be independently reconstructed later. The first full integration run against the populated pilot database failed 15 pre-existing tests that assume whole-table counts contain only Northstar; running the unchanged suite in a clean isolated migrated database passed all 64. This exposes a test isolation constraint, not a change in the M1/M2A semantics. The first UI test used a unique-text query for a phrase deliberately repeated in the UI; the query was corrected. The frozen semantic cutoff follows the recorded manual verification time, so results describe evidence available to this pilot, not complete public observation through the cutoff.

**Next action:** Review the M2B implementation and its limitations. Only after separate authorization should a later milestone assess broader real-data coverage or a sanitized public static snapshot; no M2C work began here.
