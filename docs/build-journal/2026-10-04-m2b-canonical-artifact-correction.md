# Build journal - M2B canonical artifact-byte correction

**Date:** 2026-10-04

**Problem:** GitHub Linux CI rejected the frozen selection ledger and the complete pilot replay. Windows generated the manifest byte attestation from CRLF working-tree JSON under `core.autocrlf=true`; Git stored LF JSON. The ledger declared `5644d8aea3519e67a6966f27fa5f371613e5a41413f35d8f8e039b9beb229a84`, while the committed manifest bytes hash to `d054a819ceed1fd7a0c8b478b8a9a319311bf2a653c91bf252dfce22c3203127`.

**Evidence / context:** No Git attributes pinned M2B artifact line endings. The v1/v2 manifests, selection ledger, and source-verification JSON had CRLF Windows working bytes but LF Git blobs. Both CSVs, acceptance record, expected fingerprint, and trace already had LF working bytes. The old fingerprint schema also included the manifest's file-byte hash indirectly through five strategy HYPOTHESIS Evidence source references and raw payload hashes.

**Hypothesis:** Pinning LF for all M2B JSON/CSV artifacts, rebuilding dependent attestations from those exact bytes, and separating manifest byte provenance from the semantic fingerprint will make Windows/Linux checkouts agree without changing pilot business content or outputs.

**Decision:** ADR-017 pins only `docs/pilot/m2b/*.json` and `docs/pilot/m2b/*.csv` as `text eol=lf`. Exact file-byte SHA-256 calculations remain strict. The acceptance gate additionally rejects strategy HYPOTHESIS Evidence whose source reference or raw payload hash does not attest to the current manifest bytes. Semantic fingerprint schema 1.1.0 omits only those five manifest-byte-derived transport fields from its semantic projection; it continues to hash the hypothesis topics, classifications, claims, IDs, and all account-level provenance.

**Implementation:** Normalized the four CRLF JSON working files to LF and regenerated the ledger manifest hash, acceptance record, expected fingerprint, and trace through the production pilot runner in a newly migrated isolated database. The canonical v2 manifest SHA is `d054a819ceed1fd7a0c8b478b8a9a319311bf2a653c91bf252dfce22c3203127`; the source-verification SHA changed from Windows CRLF `08db8b41bf50d5609447f7d57ea68083707732df4d20d4e9cf9ea2d64091c934` to canonical LF `9c8d6724b742ad02dd1723ffbf36a07fe145079f2c71007b0fa89396392d5a31`. Profile and leader CSV hashes stayed `b65c0ec799ef48160b9a695f4a19a7cdb37dbabb657d1770331b0e42a6ad163b` and `a9461b0363af00236726dbb5de12191bd2386efc48167b15ee55a22ffc879f44`. Both ingestion batch IDs remained unchanged. All nine checked-in JSON/CSV working artifacts now contain LF and no CR bytes. A test verifies the path-scoped attributes, exact byte hashes, and that CRLF conversion fails ledger attestation.

**Validation:** The corrected schema 1.1.0 semantic SHA-256 is `2e1d730d76b376678f71421fab7d617c20ae2a385dadc369c10201b3c81d0767` in both the original CRLF-attested and new LF-attested pilot databases. The historic schema 1.0.0 hash `0f4a444ce682e39178bfe9816f5a934634b108c4e1e971de18fddb9cd8c531aa` is no longer the current expected hash because its projection included transport bytes. The new trace's cohorts, summaries, coverage status, semantic as_of, strategy status, limits, IDs, and results exactly match the prior trace; only its fingerprint object changed. A full explicit stage replay created zero new semantic identities, reused 20 Signals, 20 States, 20 Decisions, 20 Policies, and one Action, and reused both immutable export artifacts. State's internal Signal recomputation matched. The base/coverage distributions, unmet fresh coverage slot, Relationship UNKNOWN, and absence of fabricated ABSENT, NO_MATCH, NO_ACTION, or ALLOW results are unchanged. The corrected pilot has zero Action attempts and zero operational outcomes.

**Regression:** 89 API unit tests passed; 64 PostgreSQL integration tests passed on a newly created and migrated isolated database; 17 frontend tests passed. Ruff format checked 60 files and Ruff lint passed. Strict mypy passed 52 source files; Prettier, ESLint, TypeScript, contract drift, and production Next.js build passed. `git diff --check` passed. The CI-pinned gitleaks v8.30.1 scan covered about 4.97 MB and found no leaks. A direct comparison of 13 core Northstar semantic tables between the original and corrected databases found identical rows and SHA-256 `afcd8cda2d4421b1373bc757b9f839a6ae26f7e1e58b0110c58c8b19cf869f36`. A production-mode probe returned 404 for the pilot trace and exactly three synthetic Northstar accounts on the public account route, with no pilot domain exposed.

**Result:** The repository now specifies one canonical checkout representation for byte-hashed M2B artifacts, and the acceptance gate and tests enforce it. Pilot semantics and system outputs remain unchanged. No commit, push, M2C work, provider integration, or external execution was performed.

**Failure / learning:** A byte-level artifact identity cannot depend on a developer's Git checkout conversion. A semantic fingerprint must keep file transport hashes out of its semantic projection while a separate acceptance gate verifies exact source bytes. Existing local databases populated from the old CRLF manifest fail the new gate and require a clean replay from canonical artifacts. The original M2B journal and ADR-016 remain historical records; this entry and ADR-017 correct only their byte/fingerprint details.
